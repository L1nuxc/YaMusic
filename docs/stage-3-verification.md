# Рекомендации и скорость запуска — проверка

13 ноября 2026, Windows, debug Rust, браузерная эмуляция desktop/mobile. Сверка всего исходного ТЗ: [plan-audit.md](plan-audit.md).

## Что подтверждено

- С сайта поставлен лайк настоящей песне Get Lucky (Radio Edit). В `interactions` появилась одна запись, сформировался один кластер вкуса; главная показала «Подстраивается под ваш вкус» и персональный буфер. При одном положительном треке используется один кластер, без выдуманных остальных четырех.
- Реальная INT8 CLAP CPU-модель обработала более 100 разных MP3-превью. На финальной проверке: **111 векторов**, каждый BLOB ровно 2048 байт; нормы всех векторов округляются к 1.000000. Векторы разных песен различаются: пример косинуса двух разных превью — 0.76008.
- Полная цепочка MP3 → mono → rubato 48 kHz → Slaney log-Mel → ONNX `[1,1,1001,64]` → 512 f32 работает без Python/Torch/GPU. Три окна покрывают превью; отдельный диагностический запуск с загрузкой модели занял 8.010 с. Разреженные Mel-фильтры сократили этот запуск с 19.404 с. Обычный воркер переиспользует сессию и не запускает новые вычисления во время поиска нажатой песни.
- Найдена и устранена ошибка Symphonia на пустом ID3v2-теге Deezer. Короткие неполные начальные MP3-кадры некоторых превью пропускаются декодером; сами последующие аудиокадры анализируются.
- «Моя волна» хранит текущую песню и пять вперед. При наличии обеих категорий в хвосте — три новых и две знакомых. Маленький каталог постепенно освобождает самые старые исключения истории, чтобы продолжать воспроизведение. Уже предложенные песни остаются допустимыми при быстром двойном переключении во время перестройки хвоста.
- «Микс дня» в браузере отобразил **50 настоящих песен**. Проверка всех 50 строк: ни один исполнитель не повторяется среди предыдущих трех; горизонтальной прокрутки нет. Полный микс сохраняется на UTC-день. До подготовки достаточного каталога список может быть короче и дополняться; исходный ознакомительный микс заменяется персональным после появления первых звуковых предпочтений.
- «Не нравится» у Billie Jean сохранило блокировку и переключило текущую песню. В настройках появился список исключений; «Снова рекомендовать» сняло блокировку. Тестовые лайк и дизлайк после проверки отменены через интерфейс, их активных весов в профиле не осталось. Сгенерированные тестовые рекомендации очищены; библиотека и профиль сохранены.
- После браузерного прогона при финальном просмотре кода дополнительно убрана возможность оставить дизлайкнутую песню в клиентской копии микса и следующих позициях текущей очереди. Этот небольшой финальный патч проверен TypeScript, сборкой и клиентскими тестами; отдельный повтор браузерного прогона для него не выполнялся.
- Desktop 1440×900: диалог плеера 1440×900, `clientHeight=scrollHeight=900`. Mobile 390×844: диалог 390×844, `clientHeight=scrollHeight=844`; ширина документа 390. Внешней прокрутки плеера нет. Это эмуляция, не физический телефон.
- После финального перезапуска, поиска, воспроизведения, настройки исключений и открытия микса — ошибок в браузерной консоли не зафиксировано. API `/api/health`: `status=ok`, `stage=3`.

## Запуск аудио

Исходная проблема: сервер ждал завершения обоих источников и отдельно получал полные метаданные кандидатов. Предподготовка могла занимать ту же очередь процессов, что и нажатая песня.

Теперь источники ищутся параллельно, первый доступный **прошедший проверку версии** запускается без ожидания второго. Поиск и получение потока объединены, для фона выделена отдельная квота. Сохраняются найденная ссылка и первые 256 КиБ; остальные байты продолжают поступать диапазонами, без загрузки всей песни в память. Просроченные ссылки обновляются; известная дата истечения позволяет хранить подготовку до часа вместо безусловного сброса через 10 минут. Запрос сведений о предыдущей песне отменяется при переключении; подготовка следующих начинается сразу.

| Реальный замер HTTP Range 0–1023 | До первых байтов |
|---|---:|
| Veridis Quo, первый поиск до изменения | 18.213 с |
| Та же Veridis Quo, первый поиск после изменения | 9.246 с |
| Уже подготовленная One More Time | 0.0034–0.0059 с |
| Другой подготовленный трек, во время анализа | 0.0038 с |
| Подготовленная ссылка после перезапуска сервера | 0.069 с |

Это отдельные локальные измерения, не усреднённый бенчмарк провайдеров. В браузере от нажатия подготовленной песни до отображения позиции 0:01 прошло 2.553 с; при чтении она уже играла 1.5 секунды. Первое включение совсем новой песни всё ещё зависит от внешнего поиска. Во время проверки была и кратковременная сетевая ошибка 502; мгновенное включение всего внешнего каталога не заявляется.

## Проверки кода

`npm run build` — строгий TypeScript и production Vite, успешно.

`npm test` — **7 клиентских тестов**, успешно: сохранения, очередь, безопасный вывод, LRC и фактически услышанное время. Перемотка к концу, пауза и ожидание буфера не создают ложного дослушивания.

`node scripts/rust.mjs test --offline` — **21 серверный тест**, успешно: 18 модульных и 3 HTTP-интеграционных. Покрыты в том числе:

- первые байты подготовленного трека без сети и без запуска экстрактора;
- отказ фонового поиска не затирает готовый источник;
- Range, активные читатели/LRU, фиксация файла до последнего байта;
- векторы, ID3, длительность/частота после ресемплинга;
- веса +2/+1/−1/−5, повторы, временное затухание, кластеры и негативные штрафы;
- буфер 3/2, исключение дизлайков, короткий каталог, два пропуска, расстояние между артистами;
- изоляция профилей, запрет чужой сессии, повторная доставка событий, отсутствие восстановления старого лайка после unlike;
- полная HTTP-цепочка лайк → вкус → волна → обновление → микс, в том числе гонка быстрых переключений;
- ранее сделанные каталог/WAL и кэш текста после отключения поставщика.

`npm run setup:analysis` проверен на уже установленных файлах: повторный запуск не скачивает модель заново, SHA-256 совпадает.

## Ресурсы и границы

Наблюдавшийся Windows working set: около **44 МБ** после выгрузки модели и до **186 МБ** пиково в одном из прогонов с анализом. Это не измерение Ubuntu release и не нагрузочный тест 5–10 слушателей. Модель работает одним потоком, очередь ограничена; после 30 секунд без заданий сессия выгружается. Автоматический первоначальный анализ ограничивается примерно 200 песнями (`ANALYSIS_BACKFILL_LIMIT`), реакции могут ставить дополнительные песни в очередь.

Telegram/JWT, DeepSeek, Last.fm, внешние импорты, перевод и Crossfade не объявлены готовыми. Серверный профиль сейчас привязан к этому браузеру случайным идентификатором; это ещё не облачный аккаунт.
